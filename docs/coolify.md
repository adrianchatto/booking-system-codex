# Coolify Deployment

This repo is prepared for a temporary Coolify deployment using PostgreSQL and wildcard tenant domains under `*.chatweb.com`.

## Recommended Setup

Use Coolify's Docker Compose build pack and point it at `docker-compose.yml`.

Coolify detects environment variables referenced in the compose file and shows them in the UI. Values using the `SERVICE_PASSWORD_*` format are generated by Coolify, so the repository can describe the deployment without committing real secrets.

## App Settings

- Build pack: Docker Compose
- Compose file: `docker-compose.yml`
- Exposed port: `3000`
- Health check path: `/api/health`
- Root domain: `bookingcodex.chattoweb.com`
- Wildcard tenant domain: `*.bookingcodex.chattoweb.com`

## Required Environment Variables

Coolify should discover these from `docker-compose.yml`:

| Variable | Purpose | Notes |
|---|---|---|
| `SERVICE_PASSWORD_POSTGRES` | PostgreSQL password | Generated by Coolify |
| `SERVICE_PASSWORD_NEXTAUTH` | NextAuth secret | Generated by Coolify |
| `EMAIL_ENCRYPTION_KEY` | Encrypts saved SMTP passwords | Defaults to the generated NextAuth secret in compose |
| `NEXTAUTH_URL` | Root production URL | Defaults to `https://bookingcodex.chattoweb.com` |
| `NEXT_PUBLIC_ROOT_DOMAIN` | Wildcard tenant root | Defaults to `bookingcodex.chattoweb.com` |

## SMTP Setup

Each tenant can enter SMTP details in their own **Settings & CMS** page:

| Field | Typical value |
|---|---|
| SMTP host | `smtp.gmail.com`, `smtp.office365.com`, or the SMTP host from the mailbox provider |
| SMTP port | `587` for STARTTLS, `465` for SSL/TLS |
| SMTP username | Usually the mailbox email address |
| SMTP password | Usually an app password or SMTP/API password |
| From email | The sender address customers see |
| From name | The business name or bookings team name |

SMTP passwords are encrypted before storage. The raw SMTP password is never returned to the admin UI.

## DNS

Point both records at the Coolify server or proxy target:

```text
bookingcodex.chattoweb.com      A/CNAME  <coolify-target>
*.bookingcodex.chattoweb.com    A/CNAME  <coolify-target>
```

Coolify must also have TLS configured for the apex/root domain and wildcard domain.

## Database Setup

The compose file includes PostgreSQL. For the first deploy, open the app terminal in Coolify and run:

```bash
npm run db:push
npm run db:seed
```

The seed command is safe to run on deploy. It creates or updates only the platform owner account and does not create demo businesses.

Once Prisma migrations are introduced, production deploys should use:

```bash
npm run db:migrate
```

## Tenant URLs

The app supports both existing path-based tenant URLs and wildcard subdomain routing:

```text
https://bookingcodex.chattoweb.com/bright-windows
https://bright-windows.chatweb.com
https://bright-windows.bookingcodex.chattoweb.com/admin/login
```

Self-serve tenant signup should create a tenant owner, not a platform super admin. Platform super admin access remains reserved for the platform owner.

## Booking Approval Workflow

Customer bookings are created as `PENDING` requests. Tenant admins review them in the bookings dashboard, then approve or decline:

```text
PENDING -> CONFIRMED
PENDING -> CANCELLED
CONFIRMED -> COMPLETED
CONFIRMED -> NO_SHOW
CONFIRMED -> CANCELLED
CANCELLED -> PENDING
```

The tenant dashboard shows a pending approval count so businesses can quickly see requests that need attention. Email/SMS notifications should be wired through a provider such as Resend or Twilio in a later slice.
