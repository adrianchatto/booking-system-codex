# Coolify Deployment

This repo is prepared for a temporary Coolify deployment using PostgreSQL and wildcard tenant domains under `*.chatweb.com`.

## Recommended Setup

Use Coolify's Docker Compose build pack and point it at `docker-compose.yml`.

Coolify detects environment variables referenced in the compose file and shows them in the UI. Values using the `SERVICE_PASSWORD_*` format are generated by Coolify, so the repository can describe the deployment without committing real secrets.

## App Settings

- Build pack: Docker Compose
- Compose file: `docker-compose.yml`
- Exposed port: `3000`
- Health check path: `/api/health`
- Root domain: `chatweb.com`
- Wildcard tenant domain: `*.chatweb.com`

## Required Environment Variables

Coolify should discover these from `docker-compose.yml`:

| Variable | Purpose | Notes |
|---|---|---|
| `SERVICE_PASSWORD_POSTGRES` | PostgreSQL password | Generated by Coolify |
| `SERVICE_PASSWORD_NEXTAUTH` | NextAuth secret | Generated by Coolify |
| `NEXTAUTH_URL` | Root production URL | Defaults to `https://chatweb.com` |
| `NEXT_PUBLIC_ROOT_DOMAIN` | Wildcard tenant root | Defaults to `chatweb.com` |
| `ANTHROPIC_API_KEY` | Claude chatbot key | Optional until chatbot is enabled |

## DNS

Point both records at the Coolify server or proxy target:

```text
chatweb.com      A/CNAME  <coolify-target>
*.chatweb.com    A/CNAME  <coolify-target>
```

Coolify must also have TLS configured for the apex/root domain and wildcard domain.

## Database Setup

The compose file includes PostgreSQL. For the first deploy, open the app terminal in Coolify and run:

```bash
npm run db:push
npm run db:seed
```

Do not run seed automatically on every production deploy. It creates demo tenants and users.

Once Prisma migrations are introduced, production deploys should use:

```bash
npm run db:migrate
```

## Tenant URLs

The app supports both existing path-based tenant URLs and wildcard subdomain routing:

```text
https://chatweb.com/bright-windows
https://bright-windows.chatweb.com
https://bright-windows.chatweb.com/admin/login
```

Self-serve tenant signup should create a tenant owner, not a platform super admin. Platform super admin access remains reserved for the platform owner.
